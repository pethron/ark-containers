# Developing with Compose Watch

You want the API to describe the reading list differently, and you would
rather test that sentence than repeat a build by hand after each edit.
Later you'll add a dependency, which really does change the image inputs.
Compose Watch can distinguish those changes and keep the rest of the stack
running while you work.

Use `application` with its dummy secret and the cache-enabled main stack.
From a fresh checkout, follow the [module setup](README.md), then start the
base and cache files with `up -d --build --wait`. Add a distinctive record
and retain it through both experiments.

## Keep development behavior in an override

The normal API image contains its source and dependencies; the base runtime
model has no source bind mount. `compose.dev.yaml` adds Watch rules only
when you select it. This gives the colleague receiving an image-only stack
the normal runtime, while your development session can update local code.

Open the override alongside the
[Watch documentation](https://docs.docker.com/compose/how-tos/file-watch/).
`sync+restart` copies changes under `api/src` into `/app/src` and restarts the
API process, which imports Python code at startup. `initial_sync` brings
that target up to date when the Watch session begins, and the ignore rule
excludes generated bytecode directories. Changing `api/requirements.txt`
instead triggers `rebuild`, because packages installed in an image layer
cannot be added by copying the manifest alone.

Watch requires `stat`, `mkdir` and `rmdir` in the image, plus a target the
service user can write. Our slim base supplies those utilities, and
`COPY --chown=app:app` makes `/app/src` and its files writable by UID 10001.
The packages are installed before the source copy, so a source-only build
can reuse the dependency layer. These details explain why the override works
without changing the API to run as root.

Start the development model, then start Watch in the foreground of the same
terminal. `watch --no-up` observes the already-started model; `--prune=false`
keeps superseded images instead of letting Watch prune them during the
exercise.

```text
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml -f compose.dev.yaml up -d --build --wait
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml -f compose.dev.yaml watch --no-up --prune=false
```

Wait for Watch to say it is enabled before editing. Keep that terminal open
and use another terminal in `application` for HTTP checks and service
inspection. Pressing Ctrl+C stops this Watch session; it leaves the
already-detached stack running.

## Change source and verify the response

In `api/src/app.py`, change the value of `GREETING` from
`"Team reading list"` to `"Our team's next reading list"` and save the file.
This value is returned by `/info`; the static UI heading is a different
file and is intentionally unchanged.

=== "Linux (Bash)"

    ```bash
    curl http://127.0.0.1:8080/api/info
    curl http://127.0.0.1:8080/api/books
    ```

=== "Windows (PowerShell)"

    ```powershell
    curl.exe http://127.0.0.1:8080/api/info
    curl.exe http://127.0.0.1:8080/api/books
    ```

The greeting should change automatically after sync and restart. Your
record should remain, because this restart changes the API process rather
than the database volume. During restart, a brief proxy error is possible;
wait for the API to pass readiness and retry the read.

If it stays unchanged, look for a Watch event first. A missing event suggests
the editor saved a different file or the Watch session isn't observing this
model. An event followed by an API error calls for API logs instead. This
separates file observation from application startup.

## Change a dependency and verify the installed result

Add `packaging==25.0` on a new line in `api/requirements.txt` and save.
It is a small demonstration dependency, not required by the reading-list
application. Watch should rebuild the API image and replace its container.
Record the API container ID before the edit if you want to compare it afterward:

```text
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml -f compose.dev.yaml ps -q api
```

After the rebuild finishes, verify the installed package **inside** the API,
then reread the greeting and records through the proxy:

```text
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml -f compose.dev.yaml exec -T api python -c "import packaging; print(packaging.__version__)"
```

Expect `25.0`. The new container ID and package version give evidence of a
replacement using changed image inputs; the unchanged records verify that
development left the database intact. Repeat the curl checks above. Nginx
must still route to the API even if the replacement gets another address.

The proxy uses an upstream with `resolve`, a shared-memory `zone`, and Docker's
embedded DNS resolver `127.0.0.11`, with one-second validity. Nginx 1.28
supports this dynamic upstream resolution in the open-source edition.
It can discover a new `api` address without a fixed IP or manual reload.
DNS refresh is not instantaneous failover, so requests during replacement
can still fail briefly.

## Test, then return to the image-only path

The supplied unit tests run in a separate non-root container with no network
and no secret mount. Build its image after your changes so the test container
receives the same source and dependency manifest. `--no-deps` keeps this
unit run from starting backing services, and `--rm` removes the test
container when it finishes:

```text
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml -f compose.dev.yaml build tests
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml -f compose.dev.yaml run --rm --no-deps tests
```

These tests check request validation and bounded connection retry behavior.
They are useful feedback, but they do not replace your end-to-end reading-list,
cache, persistence and recovery checks. A passing unit test alone would not
prove that Nginx can reach the recreated API.

Stop Watch with Ctrl+C. Keep your intentional source edit or restore the
original greeting in the editor; remove the demonstration `packaging` line
if you no longer want it. Then rebuild from the files you chose to keep,
without the development override:

```text
docker compose -p ark-reading -f compose.yaml -f compose.cache.yaml up -d --build --wait
```

A source change synchronized during Watch becomes part of a transferable
image only when you rebuild from that source. Keep that distinction in your
[handover](06-diagnose-and-hand-over.md), so a colleague knows which files and
images produced the result they are receiving.
